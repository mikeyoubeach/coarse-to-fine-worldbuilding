## 四、尺寸我已经量好了（如果有）

**能提前算的，全部算好给它。这是最省时间的一步。**

> 例子：围栏圈 17.1 × 15.4，你的矩形 24.2 × 15.6，所以**深度刚好、宽度差 7.1，左右各扩 3.5**。

> **同时要明说错误解法：**
> **不要把房子放大。** 房子就是原来那个尺寸，**扩的是院子**。

执行者最常见的"偷懒"是把主体现有资产整体放大来填满面积。
你不提前堵死这条路，它一定会走。

## 五、这一块特有的易错点

`<从坑清单里挑出跟这一块强相关的 3～5 条，附上为什么>`

例：
- 你这块背后是崖，**地形有高差**——所有东西必须用 `ground(x,z)`，不要写死 `y`。
- 你有一面临路且**只有一段栅栏**，边界附近留空，**别围满一圈**。
- 你是**十字形屋脊**——交叉那一侧不要用通用 `gableRoof`，它会漏一条棕色横杠（BRIEF #8）。
- 你是 **55° 陡山墙**——`gableWall` 默认内缩 0.11 只留 0.02 m 缝隙，会 z-fight
  （俯视看屋顶是一大片白碎点）。显式传 `inset: 0.28+`，端面用深木色（BRIEF #11）。

## 六、必踩的坑（整批共用，从 BRIEF 摘摘要）

| # | 坑 | 应对 |
|---|---|---|
| 1 | 负尺寸 → 整面变深紫 | 尺寸包 `Math.abs()` |
| 2 | 贴合底边被描出锯齿裙边 | 底边埋进去 |

| 4 | 圆柱必然封两端 | 开口用一圈块拼环 |
| 5 | 同时给两个轴的角度会侧躺 | `order: 'YXZ'` |
| 6 | 预设相机可能塞进房子 | 改用 `?eye=&look=` |

## 七、环境参数（**必须写死，都是主控踩过的**）

```
构建： cd <工作目录> && python build.py unit<N>
验收： python tools/check_units.py <N> --measure     # 必须 PASS，出界 0
截图： 浏览器用 --use-angle=d3d11，不要用 swiftshader
```

**为什么写设备参数**：示例项目里，用默认参数时截图是 CPU 软渲染，
实测 **13.5 FPS**；改用 `--use-angle=d3d11` 是 **60.3 FPS**。
参数没写进提示词时，几个执行者自报"13 左右，已经优化过了"。

> **执行者不会告诉你"我在这台机器上看不清"，它只会尽力在错误的条件下交差。**
